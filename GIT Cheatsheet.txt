[ 0. KHÁI NIỆM CƠ BẢN ]
--------------------------------------------------------------------------------
Working Directory  ──(git add)──>  Staging Area  ──(git commit)──>  Git Repo

• Unstaged: Thay đổi trong file chưa báo Git -> Commit sẽ KHÔNG lưu lịch sử.
• Staged: Thay đổi đã đưa vào Staging -> Commit SẼ lưu lịch sử.


[ 1. BẮT ĐẦU DỰ ÁN ]
--------------------------------------------------------------------------------
git init                     Khởi tạo repo mới tại thư mục hiện tại
git clone <url>              Clone repo từ remote về máy
git clone <url> <folder>     Clone vào thư mục chỉ định
git clone --depth 1 <url>    Clone nông (chỉ lấy commit cuối, tải cực nhanh)


[ 2. CHUẨN BỊ COMMIT (STAGING AREA) ]
--------------------------------------------------------------------------------
git status                   Kiểm tra trạng thái các file (Staged/Unstaged)
git status -s                Xem trạng thái rút gọn (gọn nhẹ)

git add <file>               Đưa 1 file cụ thể vào Staging Area
git add .                    Add toàn bộ file thay đổi / file mới
git add -p                   Chọn từng đoạn code (hunk) trong file để stage

git mv <old> <new>           Đổi tên hoặc di chuyển file (Git tự track)
git rm <file>                Xóa file khỏi đĩa cứng và stage hành động xóa
git rm --cached <file>       Xóa khỏi Git tracking nhưng ĐỂ LẠI file thật

git reset <file>             Bỏ 1 file ra khỏi Staging Area (Unstage)
git reset                    Bỏ toàn bộ file ra khỏi Staging Area


[ 3. TẠO COMMIT ]
--------------------------------------------------------------------------------
git commit                   Mở text editor để nhập message chi tiết
git commit -m "msg"          Tạo commit nhanh với message
git commit -am "msg"         Add toàn bộ file đã track + commit luôn

git commit --amend           Sửa message commit gần nhất / bổ sung file quên add
git commit --amend --no-edit Bổ sung file vào commit cũ mà giữ nguyên message


[ 4. QUẢN LÝ NHÁNH (BRANCH) & TẠM LƯU (STASH) ]
--------------------------------------------------------------------------------
git branch                   Liệt kê các branch local
git branch -a                Liệt kê tất cả branch (cả local lẫn remote)
git branch --sort=-committerdate  Sắp xếp branch theo thời gian commit mới nhất

git switch <name>            Chuyển sang branch chỉ định (hoặc: git checkout)
git switch -c <name>         Tạo branch mới và chuyển sang luôn (-b với checkout)

git branch -m <old> <new>    Đổi tên branch
git branch -d <name>         Xóa branch (an toàn - chỉ xóa khi đã merge)
git branch -D <name>         Ép xóa branch (bất chấp chưa merge)

--- Thao tác Stash (Tạm cất công việc chưa xong) ---
git stash                    Tạm lưu toàn bộ thay đổi unstaged/staged
git stash -u                 Tạm lưu cả file mới tạo (untracked)
git stash list               Xem danh sách các bản stash đang lưu
git stash apply              Áp bản stash gần nhất vào code (không xóa stash)
git stash pop                Áp bản stash gần nhất vào code VÀ XÓA stash đó
git stash drop               Xóa 1 bản stash cụ thể


[ 5. KIỂM TRA KHÁC BIỆT (DIFF) ]
--------------------------------------------------------------------------------
git diff                     Xem thay đổi chưa staged (WorkDir vs Staging)
git diff --staged            Xem thay đổi đã staged (Staging vs Commit cũ)
git diff HEAD                Xem toàn bộ thay đổi (Staging + Unstaged)
git diff --name-only         Chỉ liệt kê tên các file có thay đổi


[ 6. SOI CHI TIẾT COMMIT ]
--------------------------------------------------------------------------------
git show                     Xem thông tin và thay đổi của commit gần nhất
git show <commit>            Xem chi tiết 1 commit cụ thể
git show <commit>:<file>     Xem nội dung của file đó tại thời điểm commit cũ
git show <commit> --stat     Tóm tắt thống kê số dòng thêm/bớt trong commit

git diff <commit1> <commit2> So sánh sự khác biệt giữa 2 commit
git diff <commit> <file>     Xem file đó đã thay đổi thế nào kể từ commit đó

* Ghi chú: <commit> có thể là Hash ID, tên Branch, Tag, HEAD, HEAD~3 (lùi 3 commit).


[ 7. HỦY BỎ THAY ĐỔI (DISCARD) ]
--------------------------------------------------------------------------------
git restore <file>           Hủy thay đổi trong file (trở về commit gần nhất)
git restore --staged <file>  Đưa file từ Staged về lại Unstaged
git restore --staged --worktree <file>  Hủy sạch thay đổi file ở cả 2 nơi

git reset --hard             XÓA SẠCH toàn bộ thay đổi chưa commit (nguy hiểm!)

git clean -n                 Xem trước danh sách file rác (untracked) sẽ bị xóa
git clean -fd                Xóa thẳng tay mọi file và thư mục untracked


[ 8. CHỈNH SỬA LỊCH SỬ COMMIT ]
--------------------------------------------------------------------------------
git reset HEAD^              Undo commit gần nhất, giữ nguyên code ở Unstaged
git reset --soft HEAD^       Undo commit gần nhất, giữ nguyên code ở Staging Area

git rebase -i HEAD~6         Mở giao diện gộp/sửa/xóa 5-6 commit gần nhất

git reflog <branch>          Xem nhật ký mọi hành tung (dùng để cứu vớt commit lỡ xóa)
  └─> git reset --hard <id>  Khôi phục repo về đúng vị trí trong reflog


[ 9. TRUY CẤU LỊCH SỬ (LOG) ]
--------------------------------------------------------------------------------
git log                      Xem lịch sử commit
git log --oneline            Xem lịch sử ngắn gọn (mỗi commit 1 dòng)
git log --graph --oneline --all  Xem sơ đồ nhánh trực quan toàn bộ repo
git log <file>               Xem các commit từng làm thay đổi file này
git log --follow <file>      Xem lịch sử file (kể cả khi file từng đổi tên)

git log -G "keyword"         Tìm commit nào đã THÊM hoặc XÓA đoạn text "keyword"
git log --author="Name"      Lọc commit theo tên người viết
git log --since="2 weeks ago" Lọc commit trong 2 tuần qua
git shortlog -sn             Thống kê tổng số commit của từng thành viên

git blame <file>             Xem ai là người sửa dòng code đó vào lúc nào


[ 10. GỘP NHÁNH & GIẢI QUYẾT CONFLICT ]
--------------------------------------------------------------------------------
Ví dụ: Nhánh main = A-B-C, Nhánh feature = B-D-E

• REBASE (Đẩy gốc nhánh):
  git switch feature -> git rebase main
  => Tái cấu trúc lịch sử: D-E sẽ được bốc lên nối tiếp sau C.

• MERGE (Gộp nhánh):
  git switch main -> git merge feature
  => Tạo 1 Merge-Commit mới để nối C và D-E lại với nhau.

• SQUASH MERGE (Nén commit):
  git switch main -> git merge --squash feature -> git commit
  => Nén D-E thành 1 commit duy nhất rồi gắn vào main.

• CHERRY-PICK (Bốc lẻ commit):
  git cherry-pick <commit_id>
  => Copy riêng 1 commit từ nhánh khác gắn vào nhánh hiện tại.

* Khi gặp xung đột (Conflict):
  - Xử lý xong conflict rồi chạy:  git rebase --continue (hoặc git merge --continue)
  - Hoặc muốn hủy thao tác:         git rebase --abort    (hoặc git merge --abort)


[ 11. REMOTE - PUSH & PULL ]
--------------------------------------------------------------------------------
git remote -v                Xem danh sách Server Remote đang kết nối
git remote add origin <url>  Khai báo remote mới tên là "origin"
git remote rename <old> <new> Đổi tên remote
git remote remove <name>     Xóa liên kết remote

git fetch origin main        Tải code mới từ server về (chưa gộp vào code local)
git fetch --all --prune      Tải toàn bộ remote + dọn dẹp các nhánh server đã xóa

git pull origin main         Tải code về và tự động Merge vào nhánh hiện tại
git pull --rebase            Tải code về và Rebase đè lên trên

git push origin main         Đẩy code nhánh main lên server origin
git push -u origin <branch>  Đẩy nhánh mới lên server + liên kết theo dõi (upstream)
git push --force-with-lease  Đẩy đè lịch sử lên server (An toàn hơn --force)
git push --tags              Đẩy tất cả Tag local lên server
