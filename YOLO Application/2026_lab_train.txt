*** Frontend: tương tác và trải nghiệm trực tiếp trên một trang web/ứng dụng của người dùng (end-user)

*** Backend: bao gồm server, database, application... đóng vai trò xử lý nghiệp vụ phức tạp, tính toán logic và quản lý cơ sở dữ liệu
    - Vai trò chính:

*** API (Application Programming Interface - Giao diện lập trình ứng dụng): kết nối giữa Frontend và backend
    Người dùng thao tác trên giao diện (Frontend/ Client) --> Frontend tạo một API Request --> Backend: Nhận Request, kiểm tra tính hợp lệ, chạy thuật toán xử lý --> Backend đóng gói kết quả thành một API Response --> Frontend: Nhận dữ liệu Response và hiển thị kết quả cho người dùng theo dõi

    -- API Request: yêu cầu từ máy khách (Client) gửi lên máy chủ (server)
        Các thành phần chính:
            +) Endpoint (Địa chỉ nhận): Đường dẫn URL (Uniform Resource Locator) chỉ định chính xác nơi server đang chờ để nhận yêu cầu
            +) Method (Phương thức): Hành động máy chủ cần thực hiện
                GET (Đọc)
                POST (Tạo mới)
                PUT/ PATCH (Cập nhật)
                DELETE (Xoá)
            +) Headers (Nhãn dán/ Thông tin bổ sung): Metadata (Siêu dữ liệu) giúp máy chủ hiểu rõ hơn Request/ xác thực danh tính người gửi
            +) Body (Nội dung chính): Dữ liệu thực tế muốn gửi đi

    -- API Response: kết quả dữ liệu mà server xử lý và gửi ngược lại cho client
        +) Status Code (Mã trạng thái): 
            1xx (Thông tin): Request đã được nhận, đang tiếp tục xử lý
            2xx (Thành công): Request đã được xử lý
            3xx (Chuyển hướng): Cần thực hiện thêm thao tác để hoàn thành
            4xx (Lỗi phía Client): Client thực hiện sai 
            5xx (Lỗi phía server): Client thực hiện đúng nhưng server bị lỗi nội bộ
        +) Headers (Thông tin trả về): thông tin cấu hình server cung cấp thêm cho máy khách
        +) Body: kết quả trả về cho Client

*** Fast API
    - Framework web hiện đại để xây dựng API bằng Python
    - Công nghệ cốt lõi: 
        +) Pydantic (Chuyên gia kiểm duyệt): Chịu trách nhiệm xác thực dữ liệu (Data Validation). Khi Frontend gửi dữ liệu --> Pydantic tự điểm kiểm tra kiểu dữ liệu đầu vào (chỉ cần khai báo kiểu dữ liệu mong muốn, FastAPI tự động kiểm tra tính hợp lệ của kiểu dữ liệu, nếu dữ liệu không đúng định dạng --> trả về lỗi (mã 4xx) và không cần viết thêm mã kiểm tra thủ công)
        +) Starlette: Nền tảng giúp FastAPI xử lý các tác vụ mạng. Hỗ trợ lập trình bất đồng bộ (Asynchronous)
        +) Swagger UI: tự động sinh tài liệu 

    -- Hoạt động: Trình duyệt/ ứng dụng(Frontend) gửi yêu cầu đến đường dẫn (endpoint) cụ thể --> Kiểm duyệt dữ liệu (Data Validation): Pydantic kiểm tra định dạng file tải lên cùng các tham số đi kèm --> Xử lý (Business Logic): hệ thống thực hiện các thao tác như truy vấn Cơ sở dữ liệu, tính toán thuật toán,... theo cơ chế bất đồng bộ (Async) --> Trả kết quả (Response): gom các kết quả đầu ra (định dang JSON) thành một gói API Response hoàn chỉnh và gửi lại cho Frontend

    -- Xử lý tải file (File Upload): FastAPI cung cấp kiểu dữ liệu UploadFile, cho phép đọc nội dung file theo cơ chế bất công bộ --> tiết kiệm tài nguyên bộ nhớ
    Thuộc tính của UploadFile
        +) filename: tên file gốc được upload (str)
        +) content_type: định dạng file  (str)
        +) file: đối tượng file thực tế (SpooledTemporaryFile - class dùng để lưu trữ dữ liệu file tạm thời một các tối ưu bộ nhớ)

    Các method bất đồng bộ của UploadFile (tất cả là async - phải dùng await khi gọi):
        +) read(size): đọc dữ liệu 
        VD:    contents = await file.read()        // đọc toàn bộ nội dung file
               chunk = await file.read(1024)       // chỉ đọc 1024 byte đầu tiên
        +) write(data): ghi dữ liệu
        VD:    await file.write(b"some binary data")
        +) seek(offset): di chuyển con trỏ đọc/ghi
        VD:    await file.seek(0)                  // quay về đầu file (byte thứ 0)
        +) close(): đóng file
        VD: await file.close()


    +) Concurrency (Đồng thời): Khả năng chương trình xử lý nhiều tác vụ trong cùng một khoảng thời gian (luân phiên chuyển đổi giữa các tác vụ/ không thực thi nhiều tác vụ cùng một thời điểm)
        Phân loại tác vụ (theo đặc tính xử lý):
                I/O bound: CPU gần như không hoạt động trong phần lớn thời gian, đợi tín hiệu phản hồi từ bên ngoài
                CPU bound: CPU tính toán liên tục (xử lý, suy luận,...)

    +) Coroutine Function - đơn vị nền tảng
            Sự khác biệt giữa def (hàm bình thường) và coroutine (async def)
                def - hàm bình thường: chạy ngay lập tức từ đầu đến cuối khi được gọi, không thể dừng giữa chừng
                coroutine - async def: khi gọi không chạy ngay - tạo ra một đối tượng coroutine (như một 'kế hoạch tương lai' chưa thực thi)
                => chỉ chạy khi được đưa vào event loop ( thông qua await/ asyncio.run() )
            Ví dụ: 
            async def greet():    // coroutine function
                print("hello")

            result = greet()      // KHÔNG in ra "hello" — chỉ tạo coroutine object
            print(result)         // <coroutine object greet at 0x...>

    +) Event loop: Một vòng lặp chạy liên tục trong suốt chương trình
            Nhiệm vụ:
                Theo dõi trạng thái của các tác vụ đang chạy/ chờ đợi
                Liên tục kiểm tra: tác vụ nào đã 'sẵn sàng chạy tiếp'
                Trao quyền thực thi cho tác vụ đó cho đến khi nó gặp điểm await (diễn ra trên một luồng duy nhất)

            Ví dụ:
            async def task(name, delay):        // coroutine function (tên công việc, thời gian hoàn thành)
                print(f"{name} bắt đầu")
                await asyncio.sleep(delay)      // tạm dừng coroutine task, trả quyền điều khiển lại cho event loop --> sau khi hết delay giây, event loop cho coroutine task chạy tiếp dòng kế tiếp
                print(f"{name} hoàn tất")       // chạy sau delay giây

            async def main():
                await asyncio.gather(           // asyncio.gather(): gộp nhiều coroutine lại để chạy đồng thời
                    task("A", 2),               // coroutine objects
                    task("B", 1),
                )

            asyncio.run(main())                 // tạo event loop mới & đưa coroutine main() và chạy trong event loop đó

    +) await - cơ chế nhường quyền: tạm dừng (pause) việc thực thi hàm hiện tại để chờ tác vụ bất đồng bộ phía sau hoàn thành
            Ví dụ:
            async def detect_image(file):
                print("1. Bắt đầu đọc file")
                contents = await file.read()     // coroutine tạm dừng, quyền điều khiển được trả về event loop
                print("3. Đọc xong, xử lý tiếp")
                return contents

    Ưu điểm:
        Tái sử dụng đúng cách: tài nguyên chỉ cần được khởi tạo một lần duy nhất, sau đó được dùng lại cho mọi yêu cầu tiếp theo — thay vì tạo lại từ đầu mỗi lần
        Tách bạch trách nhiệm: mỗi phần code chỉ thực hiện 1 công việc --> dễ đọc & bảo trì

*** React: Thư viện JavaScript dùng để xây dựng giao diện người dùng UI, đặc biệt phù hợp cho các ứng dụng web dạng Single Page Application (SPA)
           React cho phép chia giao diện thành các thành phần nhỏ - Component, giúp việc phát triển, tái sử dụng và bảo trì mã nguồn dễ dàng hơn

    - Kiến trúc của React: Data → Component → Virtual DOM → DOM thật → Hiển thị

    - Creating and nesting components:
    +) Component: một phần của giao diện người dùng (UI), sở hữu logic và giao diện riêng biệt
    +) Cách khai báo: Component trong React là các hàm JavaScript trả về mã markup
    +) Quy tắc đặt tên: Tên của React component bắt buộc phải viết hoa chữ cái đầu (ví dụ: <MyButton />)
